# [팀원 요청] 용량(트리 수) 축 배포 학습 — it=1000, 8시드

## 0. 한 줄 요약

챔피언과 **완전히 같은 설정에서 트리 수만 500 → 1000** 으로 늘린 모델을 학습해 `model.pkl` 하나만 보내주시면 됩니다.
학습 시간이 길어서(약 10~14시간) 우리 기계로는 다른 작업과 겹칩니다. **컴퓨터만 빌려주시는 셈**이고 판정·제출은 저희가 합니다.

## 1. 왜 이걸 하나 (배경)

리더보드에서 트리 수만 바꿔 두 번 제출한 실측이 있습니다.

| 트리 수 | 리더보드 |
|---:|---:|
| 300 | 1040.04 |
| **500 (현재 챔피언 기반)** | **1059.05** |
| 1000 | **한 번도 안 재봄** |

트리를 200개 늘렸을 때 **+19.01** 이었습니다. 그런데 **로컬 검증(2024년 홀드아웃)은 정반대로 "300이 최고"** 라고 말합니다.
지금까지 이런 용량·정규화 축에서 로컬↔리더보드가 뒤집힌 사례가 **3/3** 이라(hand delta, 학습률 인하, 트리수 300),
**2025년 평가 데이터는 더 큰 모델을 원한다**는 가설이 섰습니다. 500 위쪽은 완전한 미탐색 구간입니다.

**핵심 트릭**: CatBoost 는 학습된 모델에서 `ntree_end=N` 으로 **앞 N개 트리만** 써서 예측할 수 있습니다.
따라서 **1000개짜리를 한 번만 학습해 두면 600·700·800·1000 후보를 재학습 없이 전부** 뽑아낼 수 있습니다.
같은 시드·같은 데이터·같은 파라미터에서 트리 수만 달라지므로 용량 축이 완벽하게 격리됩니다.

## 4. 실행

```bash
# (a) 먼저 스모크 — 3분, 경로/환경 확인용
PYTHONIOENCODING=utf-8 python -u exp/94_train_deploy.py --arm none --iterations 1000 \
    --threads <물리코어수> --out-dir out_smoke --smoke

# (b) 본 학습 — 8시드, 약 10~14시간
PYTHONIOENCODING=utf-8 python -u exp/94_train_deploy.py --arm none --iterations 1000 \
    --threads <물리코어수> --out-dir out > out/it1000_log.txt 2>&1
```
- `--threads` 는 **물리 코어 수** (논리 코어 아님). 예: 8코어면 `--threads 8`.
- 노트북이면 **충전기 꽂고** 절전 끄기 (`powercfg /change standby-timeout-dc 0`). 저희는 배터리 절전으로 10시간을 날렸습니다.
- 다른 무거운 작업과 **동시에 돌리지 마세요** (스레드 수가 바뀌면 결과가 달라집니다).
- 시드마다 `out/model/model_partial.pkl` 이 저장되므로 **중간에 멈춰도 그때까지의 시드로 쓸 수 있습니다.**

### 시간이 부족하면
8시드가 무리면 `--seeds 42,7,123,2024` (4시드, 약 5~7시간)로 줄여도 됩니다. 트리 수 비교는 **같은 모델 안에서** 하므로
시드 수가 적어도 "500 vs 800 vs 1000 중 뭐가 나은가"라는 질문에는 답할 수 있습니다. 다만 8시드가 그대로 제출 가능해서 더 좋습니다.
